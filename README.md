# architecture-medikamente

Архитектурная работа по кейсу «Медикаменте»: соответствие продукта требованиям data privacy и планирование миграции.

## Структура

В репозитории — только папки задач **Task1** … **Task6** (см. таблицу ниже и README в каждой папке).

## Итоговые артефакты по папкам

| Папка     | Содержимое |
|-----------|------------|
| **Task1** | Список проблем компании **в разрезе работы с данными** и **диаграммы потоков данных** (DFD). |
| **Task2** | Диаграмма **контекста** в модели **C4** с **проектом архитектуры MVP**. |
| **Task3** | **Таблица** с классификацией данных, **обоснованием** необходимости защиты выделенных классов и **инструментами** защиты данных. |
| **Task4** | Диаграмма **Исикавы** в **draw.io**. |
| **Task5** | **Обоснование** выбора стратегии миграции, **чётко структурированный cutover-план** и описание **мер по управлению рисками**. |
| **Task6** | Диаграмма **C2** решения — движка, реализующего классификацию данных **перед загрузкой** их в хранилище. |

# Примечания для ревьювера

Оригинальная диаграмма содержала опечатки (?) или кривую транслитерацию русских слов.
В работе я использовала английские версии, чтобы схемы выглядели целостно.
- Pacient (пациент) -> Patient - название папок
- Cassir (кассир) -> Cashier - название актора
